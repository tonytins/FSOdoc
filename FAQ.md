# FAQ

## Will FSOdoc branch into its own server and identity?

Ideally, yes. I have new names and logos ready in case it becomes feasible to create a separate server and identity for FSOdoc. However, practically speaking, it’s a complicated process. FSOdoc is based on old code that dates back to .NET Framework 3.5 and was originally written by another developer. Additionally, the FreeSO team, prefers to focus on their vision of the game, despite being an open source project using someone else's intellectual property. This is in stark contrast to others of similar origins that provide guidance on setting up your own server, FreeSO team’s approach is more restrictive. Nevertheless, I will continue to explore possibilities to create a separate server and identity for FSOdoc, taking into consideration the technical and community factors.

## What is your long-term plan for FSOdoc?

My long-term plan for FSOdoc is twofold. Firstly, I aim to document as much of the code as possible, using AI-assisted comments to make the source code more understandable and accessible. This will help users and contributors better understand the logic and functionality of the codebase, and improve the overall quality of the project.

Secondly, I plan to port over as many libraries as possible to the .NET SDK format, modernizing the codebase and ensuring compatibility with newer technologies and frameworks. This will help future-proof the project, and facilitate future development and improvements.

Additionally, I will continue to explore the possibility of creating a small server for FSOdoc, separate from FreeSO, in order to provide a distinct identity and experience for users.

## What is your vision for FSOdoc?

My vision for FSOdoc revolves around three main aspects:

1. **Names and Logos**: I have two potential names in mind for FSOdoc - "NewSO" (New Sims Online) as a homage to my original Sims fan site, New Sims 2, or "My Simulation" as a homage to an old Sims-themed RPG forum. I plan to create distinctive names and logos that reflect the purpose and identity of FSOdoc, making it easily recognizable and memorable.

2. **Game Customization**: I aim to make game customization in FSOdoc more user-friendly, allowing users to easily modify and customize the game to suit their preferences. This may involve simplifying the customization process and providing clearer documentation on how to customize various aspects of the game.

3. **Code Refactoring**: I believe that FSOdoc needs a serious refactoring effort to improve its performance and memory management. The commit history of the project reveals that it has been notorious for being a memory hog, and some flaws in the implementation of AI have been identified through AI-generated documentation. I plan to work on refactoring the codebase to optimize performance, enhance stability, and fix existing issues once I migrate things to .NET SDK.

Of course, this is all easier said than done given the complexity and age.
